Sim, faz sentido configurar o diretório do **Cacti** no Apache como uma **ligação simbólica** em vez de copiá-lo. Isso evita a duplicação dos arquivos e mantém o acesso sincronizado entre o Apache e o Nginx, já que o **Cacti** está localizado em `/cluster/www/cacti`.

Aqui está como você pode fazer isso:

---

### **Passos para Configurar o Apache com um Link Simbólico**

#### **1. Criar um Link Simbólico para o Diretório do Cacti**

Em vez de copiar os arquivos, crie um link simbólico no diretório padrão do Apache, apontando para o local onde o Cacti está instalado:

```bash
sudo ln -s /cluster/www/cacti /var/www/html/cacti
```

Isso fará com que o Apache use os arquivos no local original.

#### **2. Ajustar Permissões no Diretório do Cacti**

Certifique-se de que o Apache (usuário `www-data`) tem permissão para acessar o diretório e os arquivos do Cacti:

```bash
sudo chown -R www-data:www-data /cluster/www/cacti
sudo chmod -R 755 /cluster/www/cacti
```

Essas permissões permitem que o Apache leia os arquivos e execute os scripts PHP.

#### **3. Configurar o Apache para Servir o Cacti**

Se você ainda não configurou o Apache, edite o arquivo de site padrão do Apache:

```bash
sudo nano /etc/apache2/sites-available/000-default.conf
```

Certifique-se de que o bloco **`<VirtualHost>`** inclua as seguintes linhas:

```apache
<VirtualHost *:8080>
    DocumentRoot /var/www/html

    <Directory /var/www/html/cacti>
        Options FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

Isso configura o Apache para permitir acesso ao diretório do Cacti via link simbólico.

#### **4. Reiniciar o Apache**

Reinicie o serviço do Apache para aplicar as mudanças:

```bash
sudo systemctl restart apache2
```

#### **5. Acessar o Cacti no Navegador**

Tente acessar o Cacti diretamente pelo Apache:

```
http://<IP_DO_SERVIDOR>:8080/cacti
```

---

### **Usando Nginx como Proxy Reverso (Opcional)**

Se você também estiver usando o Nginx como proxy reverso para redirecionar as requisições para o Apache, configure o Nginx conforme os passos anteriores:

- Adicione este bloco ao arquivo de configuração do Nginx (ex.: `/etc/nginx/sites-available/cacti`):

```nginx
server {
    listen 80;
    server_name _;

    location /cacti {
        proxy_pass http://127.0.0.1:8080/cacti;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

- Teste e reinicie o Nginx:

```bash
sudo nginx -t
sudo systemctl restart nginx
```

Agora você pode acessar o Cacti usando o Nginx:

```
http://<IP_DO_SERVIDOR>/cacti
```

---

### **Conclusão**

Usar um **link simbólico** é uma boa prática, pois evita duplicação de arquivos e mantém o diretório `/cluster/www/cacti` centralizado. Certifique-se de ajustar as permissões adequadas e testar o acesso via Apache ou Nginx. Se tiver mais dúvidas ou problemas, é só avisar!
